# Domain rules

Facts about the app's domain that decide what "correct" means, or how bad a bug is, whatever any one report says. Triage and reproduce read this file every time and treat it as part of the spec. Change it by PR.

They sit here, beside the acceptance notes and plans they usually come from, not in `docs/standards/`, which is how the team works (severity, routing, confidence, labels). The app's URLs are only in `environments.json`.

Write one rule per line, and where it came from when there's a source.
